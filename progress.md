## Open

- **#14** FSM scenario runner integration: `FsmRunner` (`je_load_density/utils/scenario/fsm.py`) is exported by `__init__.py` but `run_scenario` (`wrapper/user_template/scenario_runner.py`) does not handle `mode="fsm"`. Furthermore, `fsm.py:56` terminates on self-transitions (`target == current_state`). Fix self-transitions with a loop/retry limit, wire `FsmRunner` into `run_scenario` and user templates, and add scenario tests.
- **#15** Virtual user session context & parameter isolation: `parameter_resolver` (`je_load_density/utils/parameterization/parameter_resolver.py`) stores variables in a single global dictionary. When multiple concurrent users extract values (e.g. auth tokens, session IDs) via `task["extract"]`, they overwrite each other. Introduce session-scoped / user-local context support (`${session.VAR}` or per-user local resolution) so concurrent user journeys maintain isolated state.
- **#16** Asyncio engine as a first-class runner: `je_load_density/engine/asyncio_engine.py` is not dispatched by `wrapper/start_wrapper/start_test.py`, and package initialisation imports Locust even for async callers. Add engine selection across Python/action/CLI/GUI, lazy Locust loading, request kwargs and all assertions/extractors, scenario/retry/pacing/load shapes, per-user sessions (#15), run isolation, cancellation, reports/persistence/exporters and local/master/worker parity. Track protocol capabilities explicitly; unsupported options must fail preflight. Deliver HTTP parity first without closing full parity prematurely. Design: `docs/superpowers/specs/2026-10-02-testing-platform-roadmap.md`.
- **#17** Mixed workload multi-user support: `start_test` and `prepare_env` (`wrapper/start_wrapper/start_test.py`, `wrapper/create_locust_env/create_locust_env.py`) only instantiate a single user class from `_USER_REGISTRY`. Extend `user_detail_dict` to accept a list of user types with weights (`users: [{"user": "http_user", "weight": 8}, {"user": "websocket_user", "weight": 2}]`) and pass them to Locust's `Environment(user_classes=[...])` for realistic multi-protocol simulation.

Use the run lifecycle from #16 and chart data from #26. Design: `docs/superpowers/specs/2026-10-02-testing-platform-roadmap.md`.
