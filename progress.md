## Open

- **#14** FSM scenario runner integration: `FsmRunner` (`je_load_density/utils/scenario/fsm.py`) is exported by `__init__.py` but `run_scenario` (`wrapper/user_template/scenario_runner.py`) does not handle `mode="fsm"`. Furthermore, `fsm.py:56` terminates on self-transitions (`target == current_state`). Fix self-transitions with a loop/retry limit, wire `FsmRunner` into `run_scenario` and user templates, and add scenario tests.
- **#15** Virtual user session context & parameter isolation: `parameter_resolver` (`je_load_density/utils/parameterization/parameter_resolver.py`) stores variables in a single global dictionary. When multiple concurrent users extract values (e.g. auth tokens, session IDs) via `task["extract"]`, they overwrite each other. Introduce session-scoped / user-local context support (`${session.VAR}` or per-user local resolution) so concurrent user journeys maintain isolated state.
- **#16** Asyncio engine (`bench`) feature parity: `je_load_density/engine/asyncio_engine.py` only passes `headers` and `json` body in `_send_one`. Add query parameters (`params`), form data (`data`), request labels (`name`), custom `timeout`, `expect_status` (instead of unconditionally failing status >= 400), and basic assertions (`status_code`, `contains`, `json_path`) so the lightweight engine can run realistic API tests.
- **#17** Mixed workload multi-user support: `start_test` and `prepare_env` (`wrapper/start_wrapper/start_test.py`, `wrapper/create_locust_env/create_locust_env.py`) only instantiate a single user class from `_USER_REGISTRY`. Extend `user_detail_dict` to accept a list of user types with weights (`users: [{"user": "http_user", "weight": 8}, {"user": "websocket_user", "weight": 2}]`) and pass them to Locust's `Environment(user_classes=[...])` for realistic multi-protocol simulation.
- **#18** GUI test abort control and action file execution: `je_load_density/gui/main_widget.py` has no "Stop Test" button (tests cannot be interrupted before duration completes), and only supports single-URL inputs. Add a stop button to signal the running thread/runner, add an action file picker to run `.json` test scripts directly in the GUI, and update translations in `gui/language_wrapper/`.
- **#19** Markdown summary report generator (`LD_generate_markdown_report`): Add `generate_markdown_report.py` under `utils/generate_report/` to render GFM summary tables (RPS, latencies, SLA breaches, error clusters) suitable for GitHub Actions `$GITHUB_STEP_SUMMARY` and GitLab MR comments. Register the command in `action_executor.py`, export in `__init__.py`, and add tests.
- **#20** Pre-flight health check gate: Add a target health probe before ramping load in `start_test` / `bench`. If the target endpoint is unreachable, DNS fails, or TLS handshake fails, abort early with a descriptive error instead of spawning hundreds of workers that flood logs with connection refused errors.
